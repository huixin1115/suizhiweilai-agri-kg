# 穗知未来 —— 农业知识图谱智能决策服务系统

> **AI Native 的农业决策 Web 应用**：以知识图谱为事实底座，用「图谱检索 → 本地知识库 → 大模型」三级逐级兜底生成可落地的农事方案，覆盖识病、物候、问答、处方、效益测算全链路。

---

## 一、项目简介

农业技术服务长期存在一个断层：**农户要的是"我这块地现在该干什么"，而现有工具给的是"病虫害百科词条"。**

穗知未来面向种植户与基层农技员，把分散的作物学知识组织成可推理的知识图谱，再让大模型把结构化事实转写成**能直接照着做的方案**——什么时候打药、用哪种药、安全间隔期几天、这季能挣多少。

系统已在河北民族师范学院落地试用，覆盖 52 种主栽作物，图谱规模 **1320 个节点 / 5693 条关系 / 14 类实体 / 22 类关系**，自建评测集 **875 条**问答应答对。

### 核心能力

| 模块 | 做了什么 | 技术要点 |
|---|---|---|
| 拍照识病 | 拍叶片照片 → 识别病虫害 → 接出带安全间隔期的防治方案 | 多模态大模型 + 图谱实体对齐（多级变体匹配） |
| 知识问答 | 自然语言提问 → 带依据的完整答案 | 三级检索兜底 + SSE 流式输出 |
| 物候期提醒 | 按作物/播种期推算当前物候期与待办农事 | 物候期知识 + 日期推算 |
| 决策处方 | 病虫害防治 / 水肥调控 / 农事管理 / 生产规划四类方案 | 图谱规则生成骨架 + 大模型补全 |
| 经济效益测算 | 选作物自动带入亩产、收购价与七项成本 | 参数化测算模型 |
| 经典图谱 | 左侧分类浏览、右侧关系网络可视化 | vis-network 力导向图 |

## 二、AI 技术方案（对应评分维度：AI 技术深度 35%）

### 2.1 三级逐级兜底检索（RAG）

这是系统最核心的设计。**不做"三路并行合并"**——那样既说不清答案出自哪里，又会让"图谱里没有"这件事被悄悄掩盖。

```
用户提问
   │
   ├─ ① 知识图谱 ── 规则快答 + 多跳聚合，把相关关系一次铺开
   │     │  相关度 ≥ 0.60 才认为命中
   │     └─ 命中 → 图谱事实交给大模型整理话术 → 答案带图谱依据
   │
   ├─ ② 本地知识库 ── 原始农技语料切块 + bge 向量召回
   │     │  余弦相似度 ≥ 0.58 才认为命中
   │     └─ 命中 → 语料片段交给大模型整理 → 答案标注片段来源
   │
   └─ ③ 大模型直出 ── 前两级都没有
         └─ 依据通用农技常识生成，答案里**明确标注**"非本图谱数据"
```

**为什么必须设相关度门槛**：只要问句里蹭到任一实体名（比如"葡萄园能用无人机授粉吗"里的"葡萄"），图谱聚合器就能铺出两三千字事实。不设门槛的话每一问都算命中，②③ 级永远触发不了，答案还会跑偏。

实测数据：图谱真答案相关度 0.649~0.844，纯蹭实体名只有 0.480~0.560，所以阈值定在 **0.60**（`config.py: GRAPH_HIT_THRESHOLD`）。

### 2.2 多模态识病与图谱对齐

```
图片 → 压缩(长边1280/JPEG 85) → 多模态大模型 → JSON{作物, 病害, 依据, 置信度}
                                                      │
                                          实体对齐（关键难点）
                                                      ↓
                                    图谱查防治方案（含安全间隔期）
```

**对齐是这里的真问题**：模型爱输出 `疑似小麦锈病（条锈病可能性大）`，而图谱节点是干净的 `小麦条锈病`，直接查必然落空。解法是两级：

1. **Prompt 约束**——明确禁止"疑似/可能"和括号补充，要求只输出标准病名；
2. **多级变体匹配**——依次尝试「去括号 → 去不确定修饰 → 去"病/虫害"后缀 → 取前 3 字」，取各变体最高分入库匹配。

修复后实测识病命中率 100%（score=100），识别耗时 4.4~8.0 秒。

### 2.3 AI 安全与可控性

| 机制 | 做法 |
|---|---|
| 事实约束 | 三级检索只让大模型"整理"证据，不让它凭空补充图谱没有的数据 |
| 来源标注 | 每条答案标注来自图谱/知识库/大模型，非图谱数据用显式提示段落隔开 |
| 降级兜底 | 未配置 Key、模型超时、限额耗尽时自动降级为图谱结构化作答，功能不中断 |
| 输出校验 | 识病返回强约束 JSON，解析失败回退原文而不是抛出异常 |
| 隐私 | 上传原图不落盘，仅存 480px 缩略图供历史回看；姓名/地块/产量均为演示数据 |

### 2.4 流式交互

问答与处方均走 SSE（Server-Sent Events），思考状态、分段结果实时推到前端，避免长时间白屏。

## 四、快速开始

### 4.1 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| Python | 3.10+ | 开发环境 3.10.9 实测 |
| Neo4j | 4.3.6 社区版 | 图数据库，需 JDK 11/12 |
| MySQL | 8.0 | 业务数据（也可改用 SQLite，见 4.4） |

### 4.2 安装

```bash
git clone <仓库地址>
cd 穗知未来

# 建议虚拟环境
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate

pip install -r requirements.txt
```

> ⚠ **numpy 必须锁在 2.0 以下**。torch 2.0.1 按 NumPy 1.x 编译，装 numpy 2.x 后向量检索会静默失败。`requirements.txt` 已固定 `numpy==1.26.4`。
>
> 如需 CPU 版 torch：`pip install torch==2.0.1 --index-url https://download.pytorch.org/whl/cpu`

### 4.3 配置

```bash
# 复制私有配置模板
copy code\config_local.example.py code\config_local.py    # Windows
cp code/config_local.example.py code/config_local.py      # macOS/Linux
```

打开 `code/config_local.py`，填入自己的大模型密钥：

```python
LLM_API_KEY = "ark-你自己的密钥"
```

**密钥不会进仓库**：`config_local.py` 已写进 `.gitignore`；也可改用环境变量（见 4.5）。

### 4.4 数据库

**业务库（MySQL）**：新建库后首次启动会自动建表，无需手工执行 SQL。

想让系统零依赖运行，可在 `config_local.py` 里加一行改用单文件 SQLite：

```python
DB_BACKEND = "sqlite"
```

**图数据库（Neo4j）**：启动 Neo4j 后导入图谱：

```bash
python code/scripts/08_import_extended_kg.py
```

该脚本幂等（`MERGE` 语义），重复执行不会产生重复节点；加 `--rebuild` 可清库重建。

### 4.5 环境变量（等价配置方式）

不想改文件时，全部配置都可用环境变量覆盖：

| 变量名 | 说明 | 示例 |
|---|---|---|
| `LLM_PROVIDER` | 供应商 | `doubao` |
| `LLM_BASE_URL` | 接口地址 | `https://ark.cn-beijing.volces.com/api/v3` |
| `LLM_API_KEY` | 密钥 | `ark-xxx` |
| `LLM_MODEL` | 模型名 | `doubao-seed-2-1-pro-260915` |
| `LLM_VISION_API_KEY` | 视觉模型密钥（留空复用主模型） | — |
| `LLM_VISION_MODEL` | 视觉模型名 | `doubao-seed-2-1-pro-260915` |

### 4.6 启动

```bash
cd code
python app.py
```

浏览器打开 <http://127.0.0.1:5000>。

**启动前自检**（推荐，会顺手把 Neo4j 拉起来并逐项检查依赖、配置、库表、模型连通性）：

```bash
python code/scripts/preflight.py
```
